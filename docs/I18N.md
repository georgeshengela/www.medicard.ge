# Languages (ka / en) — 2026-09-29

Owner request: the mobile app, the public site and the signed-in web app (`/app`) work in Georgian and
English. Admin (`server/admin`, `#/…` admin pages, Director, capacity, support inbox) stays Georgian only.
Georgian remains the default everywhere; existing users keep Georgian until they switch.

## Mobile (`mobile/`)

- `src/i18n/locale.js` (+ `.d.ts`): `appLang()`, `isEn()`, `tx(ka, en)`, `dateLocale()`, `setLanguageAndReload()`.
  The language is read synchronously at start (iOS UserDefaults `@medicard/pref/medicard.language`,
  Android SecureStore `medicard.language`) and is fixed for the JS runtime. Switching saves it and reloads
  the bundle (`expo-updates` `reloadAsync`, `DevSettings.reload` in dev) — so module-level constants are safe.
- `src/i18n/ka.ts` exports `ka`, which **is the active dictionary** (Georgian or English). English lives in
  `src/i18n/en/*.ts`, typed `Pick<Strings, …>`; a missing key is a type error. Never add a key to `ka.ts`
  without adding it to the matching `en/*.ts` file.
- Literal copy outside the dictionary: `tx('ქართული', 'English')`.
  - `app/**`, `src/components/**`, `src/hooks/**`, `src/store/**`: `import { tx } from '@/i18n/locale';`
  - `src/lib/**`, `src/constants/**`, `src/i18n/**` (node-tested code): relative import with extension,
    e.g. `import { tx } from '../i18n/locale.js';` (`'../../i18n/locale.js'` one level deeper).
- Dates: `toLocaleDateString(dateLocale(), …)` instead of `'ka-GE'`; month/weekday arrays pick with `isEn()`.
- The language is picked on the welcome screen (after the splash): a ქართული | English pill; the welcome
  copy follows it at once and "Get started" continues in it (reload + `setPendingRoute` → sign-in).
  Profile → Settings → Language (`LanguageSelect`) switches with a confirm and reload.
- Every request carries `X-Medicard-Lang` (`api.ts`, AI/Medi Vet streams).
- Node tests run in Georgian (no stored language), so existing Georgian assertions keep working.

## Server (`server/`)

- `src/lib/i18n.js`: `langMiddleware` sets `req.lang` from `X-Medicard-Lang` (or `?lang=`), default `ka`.
  `t(req, 'ქართული', 'English')`, `isEnglish`, `dateLocaleFor`, `aiLanguageDirective(req)`.
- `requireAuth` remembers the account language in `"User"."language"` (raw SQL, `@ignore` in Prisma,
  `prisma/20260929-language.sql`, `install-language.mjs` in `db:install`). Background senders (push, email,
  reminders) use `getUserLanguage(id)` / `getUserLanguages(ids)`.
- AI: prompts stay Georgian; append `aiLanguageDirective(lang)` to the system prompt for English users.
  Never translate or change prompts' safety rules; never send the directive for Georgian.

## Public site (`server/public/*.html`, calculators)

- `site-i18n.js` loads synchronously in `<head>` **before** `site-nav.js`. Georgian stays in the HTML;
  English goes into `data-en` (text), `data-en-html` (markup we wrote), `data-en-<attr>` (placeholder,
  aria-label, title, alt, content, value, href). Scripts use `MedicardI18n.t(ka, en)` / `MedicardI18n.locale`.
- Choice is `localStorage["medicard.lang"]`, shared with `/app`; `?lang=en` sets it (shareable links).
- Long legal pages have separate English documents linked by `<meta name="medicard:en" content="/privacy-en">`.
- The top bar (`site-nav.js`) has the ქა | EN switch (sheet on mobile).

## Web app (`server/public/app/`)

- `js/i18n.js`: same `medicard.lang` key, `t(ka, en)`, `lang`, `locale`, `setLang()` (reload).
  `api.js` sends `X-Medicard-Lang`. Language switch in the shell's account menu and on Profile.

## English style

- Warm, plain, second person ("you"), sentence case for titles and buttons ("Add medication"), US spelling.
- Product names unchanged: MEDICARD / Medicard, Medi, Medi Vet, Medi Quest, Medi Coins, MEDIRUN, MEDI COACH.
  Never "Nightingale". Metric units stay (kg, cm, kcal, km, ml).
- Medical honesty and disclaimers keep the same strength ("This is not a diagnosis — see a doctor when needed.").
- Keep short labels short (tabs, chips, buttons). English plurals: `n === 1 ? 'day' : 'days'`.
- Permission primers keep one "Continue" button (App Review 5.1.1(iv)).
- Legal texts (privacy, terms, AI consent, coach consent) are translations; the Georgian text stays the legal
  record. Consent/policy version hashes are computed from the Georgian text only — adding English must not
  bump a consent version or make anyone re-consent.

## What stays Georgian

Admin UI, Director/Telegram notices, logs, analytics names, user-written content, pharmacy product names,
admin-authored news/announcements (no English field yet), regexes that parse Georgian input.
