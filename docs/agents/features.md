## Notification Brain — Medi's own notifications (audit 2026-10-11, app 1.0.0.21.39)

The phone plans Medi's companion notifications locally (`mobile/src/lib/mediNotificationBrain.shared.ts` = pure rules, `mediNotificationBrain.ts` = runtime; ≤1 run/min on open, foreground and data changes). Rules that must hold (tests in `test:engage`): every day — tomorrow too — gets the same budget (cap = adaptive fatigue cap, ≤ admin `maxPerDay`), one of each kind (`engageKindOf`: one „how are you“ — morning/check-in/re-engage; one weekly-report nudge; one „let's move“; one water nudge), ≥90 min apart, birthday exempt; time-of-day families (`DAY_BOUND_FAMILIES`) are skipped (`quiet_hours` / `window_passed`), never pushed into tomorrow; the morning greeting never moves to the person's usual hour; check-in copy follows the delivery hour; the open that starts a run counts (`markEngageAppOpen` first). Delivery: the system shows a notification without the app, so each run first reconciles the previous run's plans whose time passed (`reconcileDeliveredPlans` → sent log, fatigue outcome, server `delivered`); the foreground handler (`noteEngageShown` in `notifications.ts`) and taps (`markEngageOpened` with the decision id) count their own; the `_layout.tsx` received-listener must not (it fires for dropped ones too). One server row per plan: `stabilizeEngageDecisions` keeps a plan's id while it moves, turns a held-back pending plan into its `CANCELLED` row, and only changed rows are synced (index `medicard.engage.decisionIndex.v1`). Weekly „seen“ is per week (`weeklySeenState`). Admin control: Push → „Medi-ს შეტყობინებები“ → „მართვა“ (`/api/admin/notifications/brain-config`, table `NotificationBrainConfig`, `install-notification-brain.mjs`; phones read `brain` from `/api/app/status`, app `brainRemoteConfig.ts`): pause all (`admin_paused`), switch a family off for everyone (`admin_off`), daily ceiling. Server analytics count plans, not runs (`collapseDecisionPlans` also marks old phones' replaced plans `superseded`; the admin dashboard counts the same rules in SQL — `loadBrainPlanStats`, change both and run `server/scripts/brain-plan-parity.mjs`); the log is `listNotificationPlans` with statuses delivered / pending / unconfirmed / cancelled / blocked. Copy: `server/src/lib/pushEngageTemplates.js` and the app fallback `mediEngageCopy.ts` must stay equal (test). New family = rules + `ENGAGE_FAMILIES` + `BRAIN_FAMILIES` (server) + admin `BRAIN_GROUPS`/`BRAIN_FAMILY_WHEN`/`BRAIN_FAMILY_KA` + copy in both files.

## Reminders always on (owner 2026-10-02, app 1.0.0.18.19)

Owner: every reminder is on by default and each can be turned off on Profile → შეტყობინებები → „შეხსენებები“ (`ReminderFamiliesSection`). One switch per family: meds, visits, pets, pregnancy, nutrition live in `src/lib/reminderPrefs.ts` (missing = on; only an explicit `false` from a switch turns one off; meal settings writes the same value, the server row only holds meal times); cycle uses `cycleReminderPrefs.enabled`; steps/weight use the goal's own `reminderEnabled`. Every sync function checks its switch and cancels its prefix when off. Pet care never reminded before: server schedules were created with `reminderEnabled:false` (now true, offsets [1,0]; `install-pet-reminders.mjs` turned existing ACTIVE schedules on once, marker table `OneTimeDataFix`), the device opt-in default was false and written back on every sync (now the pets switch), and overdue care had no follow-up (now 1/3/7/14/30 days then monthly for a year, next two queued, `PET_CARE_OVERDUE_STEPS`). `reconcileAllLocalReminders` (`src/lib/reminderReconcile.ts`) restores visits, meals, steps and weight after sign-in (after the account pull) and on foreground (≤ every 10 min), with a once-per-account switch-on of old default-off goals and cycle prefs; `reconcileCycleReminders` also does pregnancy care; a fresh notification grant schedules every family at once. Medication courses that started and end > 60 days out use repeating DAILY/WEEKLY triggers (dated slots only near the end — dated ones ran out after ~2 weeks). Android cycle/steps/weight/nutrition channels are `*-v2` at HIGH (old ids deleted). Never add a reminder family without a switch in that section and a call in the reconcile.

## Sleep hours (owner 2026-10-11, app 1.0.0.21.42)

Sleep totals (`HealthMetricDaily.sleepHours`) come only from Apple Health (`HKCategoryTypeIdentifierSleepAnalysis`) / Health Connect (`SleepSession`), plus a total the user tells Medi. MEDISLEEP (2026-10-12, docs/agents/sleep.md) keeps its own nights in `SleepNight` and does not write `sleepHours`. Medi's weekly report (`app/week.tsx`, `mediWeekReport.ts`), the health-metrics card, Medi context, MEDICOACH and cycle all read `HealthMetricDaily.sleepHours`. Count nights with `src/lib/sleepNights.ts` only: asleep pieces (iOS values 1/3/4/5, Health Connect stages 2/4/5/6), in-bed/session time only for a day with no asleep data, overlapping sources counted once, a night belongs to the wake-up day (18:00 → 18:00), read the whole window (`limit: -1`, from `sleepQueryStart`). Before this, every piece was summed (in-bed + awake + stages, iPhone + Watch) and the server kept `Math.max`, so 7 h showed as 12–15 h and never came down; the server now keeps the last value. Days older than the 7-day read window keep their old values.

## Calories and water on the health card (2026-10-11, app 1.0.0.21.43)

`HealthMetricDaily.nutritionKcal` has two writers: the phone's Apple Health (`DietaryEnergyConsumed`, incl. MEDIFOOD write-back) / Health Connect (`Nutrition`) read — the day's **total**, sent again on every read — and a person's own entry (health card `logManualHealthMetric`, Medi `metric_record`) — an **addition**. The sync route used to add both, so every later device read added the whole day again (latent: on 2026-10-11 the main DB had 91 calorie rows from one account, all < 2 200 kcal). Now (`server/src/lib/nutritionKcalSync.js`): app 1.0.0.21.43+ sends device totals as `nutritionKcalTotal`, which replaces only the device part; `nutritionKcal` stays an addition and is also kept in `"nutritionKcalAdded"` (raw SQL, Prisma field `@ignore`, `install-health-nutrition-added.mjs`), so stored = device total + additions and neither writer erases or repeats the other. Older builds send device totals as `nutritionKcal`; a request with several days or step logs is their device read and counts as totals (a manual entry and Medi always send one day and no step logs) — never send a multi-day addition. No column (before db:install, failed read) fails open: a total replaces the value, the sync never fails. The health card merges a day the phone read and the server stored as one value, the larger of the two (`mergeDayTotals` for nutrition and hydration; summing doubled the sparkline); sleep keeps the phone's night. Tests: `server/src/lib/nutritionKcalSync.test.js` (route with an in-memory Prisma), `mobile/src/lib/healthMetricsStorage.test.ts`.

## MEDIFOOD core polish (owner 2026-10-12, app 1.0.0.23.2)

From the market + usage analysis (`reports/MEDIFOOD ბაზრის ანალიზი.md`, local only): 86 % of meals come from AI text/photo, most people stop before the first meal, and the target refused most women. Polish the core, no new breadth. Rules now:
- **Target** (`nutritionProgram.js`): floors `CALORIE_FLOOR` women 1 200 / men 1 500 (NHLBI 2013; a clinician should confirm before lowering), ceiling 3 500, age 18–78. A loss below the floor is clamped to it (`paceLimited`, `weeklyKg`) while ≥ 100 kcal of room remains under maintenance; otherwise the only reason is `LOSE_NO_ROOM_REASON` with `fallback: {mode:"maintain"}`. Never clamp a deficit into a surplus. The wizard shows the same numbers live from step 2 (`mobile/src/lib/nutritionTarget.js`; a server parity test keeps them equal) and offers „წონის შენარჩუნება“ instead of a dead end.
- **The target never switches off for success**: `programState` recalculates it for a new weight (±2 kg), a new weight goal, or a reached goal (→ maintain) (`currentProgramConfig`, dashboard `adjusted` + `currentConfig`); 28 days is only a soft `reviewNote`. `needsReview` is left for real refusals (pregnancy mode, conditions, BMI…).
- **Hub**: nothing logged today → the hero is „რა ჭამე?“ (photo + say/type, an example marked as an example) and the LogBar drops its duplicate camera/say (`heroCovers`); the meal plan card sits under the day's meals.
- **Photo**: the estimate starts as soon as the photo is taken (no „შეფასების დაწყება“ tap); edit-form grams rescale every nutrient (`rescaleFoodFields`). Never „ზუსტია“: low uncertainty reads „მიახლოებითი შეფასება“ (app + web); rich dishes get a hidden-fat note.
- **AI estimate**: `reasoning: {effort: "low"}` for speed; grounded on the catalogue — photo prompts list every `ge: true` dish in English (`georgianReference`), text/fix prompts list only the foods the words name (`describedReference`, fillers like „ორი“ skipped). Catalogue 183 foods (102 `ge`, composite dishes `quality: "estimate"`).
- **Search** understands Georgian endings by stem (`kaStem`: ხინკლები / ხინკალს → ხინკალი; same stem only, as-written matches rank first) and local hits no longer wait for Open Food Facts/USDA beyond 1.5 s.
- **Medi `nutrition_log`**: apps that send `X-Medicard-Caps: nutrition-review` get a native handoff to `/nutrition/diary` (`nutritionLog` payload in memory, never the URL); the diary estimates the words and shows the review, Save writes Health too. Older JS and the web keep the one-step `/quick-log`.
- **Meal plan**: 26 Georgian home recipes (ლობიო მჭადით, ჩიხირთმა, ფხალი, ოსტრი, კალმახი…) from USDA SR Legacy ingredients (proxies named in `nameEn`), installed by `install-nutrition.mjs` (`ON CONFLICT DO NOTHING`). Gap: a vegan without nuts gets Georgian lunch/dinner only.
- Not changed (owner decision pending): meal reminders still go to every account with notifications on.

## Nutrition · Cal AI parity (2026-09-26, app 1.0.0.12.0)

`/nutrition/diary` logs food eight ways from one `+` menu: photo, gallery, barcode (`expo-camera` viewfinder → Open Food Facts via our server, code only), label scan, describe/dictate (text mode, no photo), search (saved → Georgian catalog `server/src/data/nutrition-catalog.json` → Open Food Facts / optional USDA), saved/recent, manual. `POST /api/nutrition/estimate` takes `mode=photo|label|text|fix`; only text and fix may omit the photo. Health score is a deterministic heuristic (`healthScore`), never AI. Budget = target + burned (if `addBurned`) + rollover ≤200 (if `rollover`), from `NutritionPreference`. Streak, week summary, projection, water/steps, measurements and activities ride on the dashboard. Meal reminders use the `nutrition:` prefix. Medi action `nutrition_log` → `/api/nutrition/quick-log`. Keep estimates unsaved until the person confirms; never claim accuracy. 2026-09-27 (app 1.0.0.13.0): macro split (re-divides plan calories only), meal/day copy, personal recipes (`NutritionFood.source='recipe'`), opt-in Apple Health / Health Connect write-back and an intermittent-fasting timer — daily 10–20 h windows only; never offer it under 18, in pregnancy/breastfeeding or with an eating-disorder history; glucose-lowering medication needs the person's doctor confirmation; no ketosis/autophagy claims. Quest still excludes calories; widgets/HealthKit write-back are a separate native train. See docs/NUTRITION.md.
