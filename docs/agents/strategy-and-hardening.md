# Strategy fixes and launch hardening

Rules from the 2026-10 strategy deck and the launch bug hunt. They touch several areas (steps, MEDIQUEST, Medi, accounts, onboarding, cycle, doses); the area files link here.

## Strategy quick fixes (owner 2026-10-08, app 1.0.0.21.19)

From the 2026-10-06 strategy deck (`docs/strategy-2026/`, branch `claude/busy-turing-myk1kq`); the owner approved this package. Keep these rules:
- **Personal step goal.** The daily step goal is the median of the days with steps among the last 14 finished days (today excluded, ≥ 3 such days), rounded to 500, **plus 500** (a reachable stretch), kept within 2 000–10 000; fewer days → 4 000. One rule in `mobile/src/lib/personalStepsGoal.ts` and `server/public/app/js/stepsGoal.js` (web has no build step), one table of cases tests both (`personalStepsGoal.test.ts`). `fetchStepsMetrics` feeds it the server's daily rows plus the phone's last week only, so every chart tab shows the same goal. Never bring back a fixed 10 000 default. The goal wizard (`stepsGoal.ts`), MEDIQUEST's adaptive target and MEDIRUN presets are not merged into it yet.
- **No app-open streak in the UI.** No header pill, no daily full-screen celebration (`DailyCheckInHost` no longer navigates), no streak engage pushes; nothing links to `/profile/streak` (the route stays for old pushes). The server claim on `GET /api/auth/me` and `DailyCheckIn` rows stay for older builds (`DAILY_LOGIN_POINTS = 0`). Guard: `mobile/tests/app-open-streak.test.cjs`. Streaks built on health actions (MEDIQUEST, meals, fasting, steps goal, MEDIRUN) stay.
- **Check-in notification** has no „კარგად ვარ“ action (it stored nothing); old delivered notifications with it still open safely.
- **No coins for daily AI chats.** `daily_medi` is retired; `weekly_medi` = one Medi consultation in the ISO week, XP only (0 coins), target fixed at 1, offered only after the current AI consent was accepted (cancelled on revoke), never counts for the daily streak — enforced in `ensureQuestTemplates` even for admin-edited rows. The rare MEDI_3…MEDI_100 milestones keep their coins (never take away a reward people are working toward without notice).
- **Invite copy** says both people get 25 Medi Coins right away when the code is entered (Profile → „მოიწვიე მეგობარი“ → „მოწვევის კოდი მაქვს“); never „100 coins after the first entry“.
- **Medi's clinical mode** is labelled „კონსულტაცია“ / "Consultation" everywhere (app, web, Medi's own catalogue); never „Medi ექიმი“ / "Medi doctor". `about.html` describes the one Medi chat with the „კონსილიუმი“ switch.
- **No hidden onboarding score.** Onboarding makes no AI call; `/api/health-profile/onboarding-analysis` answers older builds with the profile only; the results/score screen and `HealthScoreGauge` are deleted. Never compute a health score nobody sees.
- **Skipped and missed doses are amber, not red** (`hubInk('amber')`, `doseStatusColor`; web `--med-missed`, `.badge-amber`). Red stays for deleting and real alerts. Guard: `mobile/tests/dose-status-colour.test.cjs`.
- Admin news examples never suggest a draw („გათამაშება“).

## Launch hardening, train 1 (owner 2026-10-08, app 1.0.0.21.20)

People are signing up; the owner asked for no bugs that cost trust. A bug hunt confirmed 61 findings; the first batch is fixed. Server first, then the OTA — every server change stays compatible with app builds 1.0.0.21.0–.19. Keep these rules:
- **Accounts are never deleted as „empty“ by mistake.** `accountHasContent` (`server/src/lib/accountLogins.js`) also counts cycle tags/classifications/pregnancy plan, `RewardLedger`, MEDIRUN sessions/claims/crews, and person-made rows of mixed tables through `CONTENT_PREDICATES` (CycleProfile answers, HealthProfile clinical lists and typed logs, partner shares, referrals, trainer links); a missing table/column is skipped, an error fails closed. `POST /api/auth/me/discard-new` is refused (409 `DISCARD_NOT_ALLOWED`) once onboarding started (`discardNewBlocker`); app and web ask „MEDICARD უკვე გამოგიყენებია?“ only before that.
- **Sliding sessions.** `GET /api/auth/me` adds `token` once the presented JWT is past half its lifetime (`server/src/lib/sessionRenewal.js`); tokens with an `aud` (the Medi action seal) are never renewed. The app stores it with `renewToken` (only while the asking token is still the saved one, last after hydrate's guards — a sign-out in between wins); web `session.js` the same. The AI-consent request check compares the JWT subject, not the raw token.
- **SMS codes:** a new code is valid only after its SMS really went out (earlier codes stay valid until then; a failed/capped send closes it at once); daily caps count only SENT/QUEUED. `authErrorMessage` maps only the exact sign-in failure text — a wrong or expired code shows the server's own message.
- **Onboarding has no dead end.** The final save retries twice on 0/429/5xx only (`finishRetryDelay`; 408 and other 4xx never), then shows the error with „ხელახლა ცდა“ and a sign-out link; every question has a quiet sign-out (`OnboardingExit.tsx`: stay / sign out / delete), under 18 offers delete directly, the privacy decline opens the same card, a failed privacy save shows its error, and a failed notification save carries the answer in memory (`withExtraAnswers`).
- **Cycle:** `PUT/DELETE /api/cycle/logs/:date` drop the stored last period start only when logged bleeding is actually removed (`lastPeriodTouches`). Undo of the one-tap „მენსტრუაცია დაიწყო“ restores the exact day (`periodStartUndo` / `periodStartUndoDay`, never a false „no bleeding“, never deletes notes logged after the tap) and re-posts the last period start when the server lost it. Home shows „late“ only with the server's late alert; defaults or < 2 logged cycles read „ვსწავლობთ შენს რიტმს“.
- **Medi privacy:** the MEDIFOOD block rides with a clinical answer only when her own words are about food, eating, fasting or weight (allergens always); answers store `cycleContext`, and while the cycle is withheld (lock, privacy mode, discreet notifications, removed context) earlier consultations that carried or mention the cycle are left out. No disclosure or consent-version change.
- **Doses from notifications:** „მივიღე ✓“ resolves the account first and, with no readable session (cold start), waits in a 24 h device queue; the dose is dated by the notification's delivery time; medication caches are invalidated. `pullAccountState` merges a mark made during the request instead of overwriting it.
- **Quest rewards are frozen at completion** (`UserQuest.metadata.reward`); a `daily_medi` row completed before its retirement pays its old 10 coins. `GET /api/quests` and `/history` hide `weekly_medi` from app JS older than 1.0.0.21.19 (`X-Medicard-App-Version`).
