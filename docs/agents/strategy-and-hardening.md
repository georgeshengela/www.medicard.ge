# Strategy fixes and launch hardening

Rules from the 2026-10 strategy deck and the launch bug hunt. They touch several areas (steps, MEDIQUEST, Medi, accounts, onboarding, cycle, doses); the area files link here.

## Strategy quick fixes (owner 2026-10-08, ships with app 1.0.0.21.28)

From the 2026-10-06 strategy deck (`docs/strategy-2026/`, branch `claude/busy-turing-myk1kq`); the owner approved this package. Keep these rules:
- **Personal step goal.** The daily step goal is the median of the days with steps among the last 14 finished days (today excluded, ≥ 3 such days), rounded to 500, **plus 500** (a reachable stretch), kept within 2 000–10 000; fewer days → 4 000. One rule in `mobile/src/lib/personalStepsGoal.ts` and `server/public/app/js/stepsGoal.js` (web has no build step), one table of cases tests both (`personalStepsGoal.test.ts`). `fetchStepsMetrics` feeds it the server's daily rows plus the phone's last week only, so every chart tab shows the same goal. Never bring back a fixed 10 000 default. The goal wizard (`stepsGoal.ts`), MEDIQUEST's adaptive target and MEDIRUN presets are not merged into it yet.
- **No app-open streak in the UI.** No header pill, no daily full-screen celebration (`DailyCheckInHost` no longer navigates), no streak engage pushes; nothing links to `/profile/streak` (the route stays for old pushes). The server claim on `GET /api/auth/me` and `DailyCheckIn` rows stay for older builds (`DAILY_LOGIN_POINTS = 0`). Guard: `mobile/tests/app-open-streak.test.cjs`. Streaks built on health actions (MEDIQUEST, meals, fasting, steps goal, MEDIRUN) stay.
- **Check-in notification** has no „კარგად ვარ“ action (it stored nothing); old delivered notifications with it still open safely.
- **No coins for daily AI chats.** `daily_medi` is retired; `weekly_medi` = one Medi consultation in the ISO week, XP only (0 coins), target fixed at 1, offered only after the current AI consent was accepted (cancelled on revoke), never counts for the daily streak — enforced in `ensureQuestTemplates` even for admin-edited rows. The rare MEDI_3…MEDI_100 milestones keep their coins (never take away a reward people are working toward without notice).
- **Invite copy** says both people get 25 Medi Coins right away when the code is entered (Profile → „მოიწვიე მეგობარი“ → „მოწვევის კოდი მაქვს“); never „100 coins after the first entry“.
- **Medi's clinical mode** is labelled „კონსულტაცია“ / "Consultation" everywhere (app, web, Medi's own catalogue); never „Medi ექიმი“ / "Medi doctor". `about.html` describes the one Medi chat with the „კონსილიუმი“ switch.
- **No hidden onboarding score.** Onboarding makes no AI call; `/api/health-profile/onboarding-analysis` answers older builds with the profile only; the results/score screen and `HealthScoreGauge` are deleted. Never compute a health score nobody sees.
- **Skipped and missed doses are amber, not red** (`hubInk('amber')`, `doseStatusColor`; web `--med-missed`, `.badge-amber`). Red stays for deleting and real alerts. Guard: `mobile/tests/dose-status-colour.test.cjs`.
- Admin news examples never suggest a draw („გათამაშება“).

## Launch hardening, train 1 (owner 2026-10-08, ships with app 1.0.0.21.28)

People are signing up; the owner asked for no bugs that cost trust. A bug hunt confirmed 61 findings; the first batch is fixed. Server first, then the OTA — every server change stays compatible with older app builds. Keep these rules:
- **Accounts are never deleted as „empty“ by mistake.** `accountHasContent` (`server/src/lib/accountLogins.js`) also counts cycle tags/classifications/pregnancy plan, `RewardLedger`, MEDIRUN sessions/claims/crews, and person-made rows of mixed tables through `CONTENT_PREDICATES` (CycleProfile answers, HealthProfile clinical lists and typed logs, partner shares, referrals, trainer links); a missing table/column is skipped, an error fails closed. `POST /api/auth/me/discard-new` is refused (409 `DISCARD_NOT_ALLOWED`) once onboarding started (`discardNewBlocker`); app and web ask „MEDICARD უკვე გამოგიყენებია?“ only before that.
- **Sliding sessions.** `GET /api/auth/me` adds `token` once the presented JWT is past half its lifetime (`server/src/lib/sessionRenewal.js`); tokens with an `aud` (the Medi action seal) are never renewed. The app stores it with `renewToken` (only while the asking token is still the saved one, last after hydrate's guards — a sign-out in between wins); web `session.js` the same. The AI-consent request check compares the JWT subject, not the raw token.
- **SMS codes:** a new code is valid only after its SMS really went out (earlier codes stay valid until then; a failed/capped send closes it at once); daily caps count only SENT/QUEUED. `authErrorMessage` maps only the exact sign-in failure text — a wrong or expired code shows the server's own message.
- **Onboarding has no dead end.** The final save retries twice on 0/429/5xx only (`finishRetryDelay`; 408 and other 4xx never), then shows the error with „ხელახლა ცდა“ and a sign-out link; every question has a quiet sign-out (`OnboardingExit.tsx`: stay / sign out / delete), under 18 offers delete directly, the privacy decline opens the same card, a failed privacy save shows its error, and a failed notification save carries the answer in memory (`withExtraAnswers`).
- **Cycle:** `PUT/DELETE /api/cycle/logs/:date` drop the stored last period start only when logged bleeding is actually removed (`lastPeriodTouches`). Undo of the one-tap „მენსტრუაცია დაიწყო“ restores the exact day (`periodStartUndo` / `periodStartUndoDay`, never a false „no bleeding“, never deletes notes logged after the tap) and re-posts the last period start when the server lost it. Home shows „late“ only with the server's late alert; defaults or < 2 logged cycles read „ვსწავლობთ შენს რიტმს“.
- **Medi privacy:** the MEDIFOOD block rides with a clinical answer only when her own words are about food, eating, fasting or weight (allergens always); answers store `cycleContext`, and while the cycle is withheld (lock, privacy mode, discreet notifications, removed context) earlier consultations that carried or mention the cycle are left out. No disclosure or consent-version change.
- **Doses from notifications:** „მივიღე ✓“ resolves the account first and, with no readable session (cold start), waits in a 24 h device queue; the dose is dated by the notification's delivery time; medication caches are invalidated. `pullAccountState` merges a mark made during the request instead of overwriting it.
- **Quest rewards are frozen at completion** (`UserQuest.metadata.reward`); a `daily_medi` row completed before its retirement pays its old 10 coins. `GET /api/quests` and `/history` show `weekly_medi` to native app JS only when it sends `X-Medicard-Caps: weekly-medi` (`CLIENT_CAPS` in `api.ts`, `WEEKLY_MEDI_CAP` in `quest.js`); never gate on a version number — OTAs from other branches reuse the numbers. Web and unversioned requests get everything.


## Launch hardening, train 2 (2026-10-09, ships with app 1.0.0.21.28)

Second batch of the bug hunt (22 findings). Server first (adds `User.passwordChangedAt` through `npm run db:install`), then the OTA. Keep these rules:
- **A password reset ends every older session.** Email, SMS and QA resets write `"User"."passwordChangedAt"` (raw SQL, `@ignore`, `install-password-changed.mjs`); `requireAuth` and both socket handshakes (default namespace and `/community`) refuse a token whose `iat` is more than 5 s older (401 `TOKEN_EXPIRED`), before `GET /me` can renew it. Fails open with no column, no value or a read error (`server/src/lib/sessionRevocation.js`). The read is deliberately uncached. Sign-out stays local-only (per-token revocation would cost another read per request). Adding an email is not a password change.
- **SMS codes:** only `PhoneVerification.codeHash` is checked; `SmsLog` keeps OTP digits masked at rest and in `/api/admin/sms/logs` (no reveal button, OTP text not searchable). Account deletion redacts the number's sign-in rows in every spelling (`phoneLookupValues`, only `userId` NULL rows) and deletes `EmailVerification` rows. Phone sign-in for a new number answers 403 `REGISTRATIONS_CLOSED` while registrations are closed; existing accounts sign in as before. The add-email „აქ გადმოტანა“ keeps the password chosen with the code (sealed in the conflict token).
- **Medi streaming:** closing Medi mid-answer is Stop — the app aborts, the server aborts the provider and stores, charges and logs nothing (`watchStreamClient`, `runTrackedAi` `cancelled()`; no `AiInteraction` ERROR row for a person who left). A screen opened over Medi does not cancel: the answer finishes and is saved in the thread. A network drop or timeout removes the bubble and puts the question back with „ხელახლა ცდა“. A 403 `AI_CONSENT_REQUIRED` forgets the 15-minute consent memory so the retry opens the real sheet. AI limit copy is the server's own words; a generic `RATE_LIMITED` with a wait reads in seconds / minutes / hours. A voice question gets the start of the answer spoken (~600 characters, whole sentences) only for voice input, with the admin `voice` switch on and not muted.
- **Cycle:** the partner page is paused (`paused: true`, no period, phase, fertile window or symptoms, never the mode name) in pregnancy, postpartum and under the postpartum-return gate; the owner sees a pause note under the link. Settings routes answer a whole bundle or `null`, never a partial one; every cache/view write checks `isCompleteCycleBundle`. New app JS and web /app skip `null` and refetch; pre-OTA JS shows a false generic error on the partner-link toggle and the profile save when the reload fails twice (the write is saved) — never answer old builds a partial body or `{}`: they cache any object as the whole bundle and /cycle crashes. AI cycle tips are keyed by language and cleared when the last period start or averages change. More than 8 custom tags never loses the day (app and server agree on 8).
- **Doses:** a medication reminder opens the reminded slot (`/medications/<id>?time=&date=`). „გადატანა“ = `pending` + `rescheduledTo` + a one-off `med:<id>:moved:<date>:<slot>` reminder, never TAKEN; a taken dose cannot be moved; Home's undo of a moved dose restores the move (`reopenDose`). Only taken/skipped answer a dose; the calendar never shows a pending dose as taken. A failed delete shows the error; reminders are cancelled only after the delete succeeded (or 404).
- **Onboarding:** a medicine typed in the medications goal step shows a Home card „დააყენე შეხსენება: …“ that opens MEDIPILL setup with the name filled in (`src/lib/home/medicationSetup.ts`); no dose or time is invented. The placeholder name „Medicard“ is never shown as a person's name (`realFullName` in `displayName.ts`, guarded by a sweep test). A failed last-period save in the cycle goal step blocks Finish with the message (Skip continues without a date). A man cannot keep `primaryGoal: 'cycle'`. The cycle goal step explains a disabled Continue. „დაასრულე პროფილი“ opened from Home returns to Home.

## Launch hardening, train 3 (2026-10-09, ships with app 1.0.0.21.28)

The rest of the bug hunt (app only, plus MEDIPILL validation copy on the server). Keep these rules:
- **Cycle → Health:** `planCycleHealthWrite` (`src/lib/cycleHealthWrite.ts`) writes only what a save changed against the stored day (`base` — every `persistCycleLog` caller passes it); a cycle start only for „დღეს დაიწყო“ or bleeding newly added with no period running into it (`continuesLoggedPeriod` bridges 2 unlogged/spotting days like the server; an explicit „none“ ends a period). Fire-and-forget, never requests Health access; every iOS flow sample carries `HKMenstrualCycleStart` true/false.
- **Cycle sheets** (quick log, day sheet, sex sheet) fill from the cached cycle view (`useCycleDayForm`, owner-checked, no `loadCycleView` per open or swipe); a background refresh rebases only untouched fields (`rebaseCycleForm`). `sexualActivity: false` („არ მქონია“) survives later saves (`sexualActivityForSave`). One-tap actions that stored nothing show `ka.cycle.saveNotPersisted` (no toast, haptic or funnel event); /cycle shows action errors inline (guard `tests/cycle-one-tap-errors.test.cjs`). A sheet for another day names that day.
- **MEDIPILL:** `/api/medications` answers validation errors with our own Georgian reason (English via `FIELD_MESSAGES_EN`), never zod's English defaults. `MAX_TIMES_PER_DAY = 8` app = server = web. The setup form never saves `daysOfWeek: []` (every reader treats empty as daily; the server still accepts it from old builds and Medi — never change that meaning). Refill fields are stored but hidden on app and web; nothing counts stock — bringing it back needs real stock tracking in a store train. The hub shows `MedicationRemindersNote` when notifications are off (never asked → one-button „გაგრძელება“ primer; denied → „პარამეტრების გახსნა“; a grant refetches medications so reminders are scheduled). Home's „დააყენე შეხსენება“ card has „არა ახლა“ (device, per account, `medicard.home.medSetupDismissed.v1.<userId>`).
- **Account delete:** the server first, nothing local before it confirms; then cancel reminders, forget device data and clear the token with no further network call (push tokens cascade with the user). Email sign-in has no „Remember me“ — sessions are kept and slide; never add a session-only mode without real storage behind it.
- **MEDIRUN location:** once the OS answered no (`canAskAgain === false`) PulseActive shows „პარამეტრების გახსნა“ instead of „მდებარეობის მიღება“; returning to the app only re-reads the permission. Barcode scanner: same rule as the QR scanner (one „გაგრძელება“ primer until the camera question is answered, then Settings).
- **Nutrition:** a failed `GET /api/nutrition/settings` is never an AI pause (`aiEstimatesAvailable` = `photoEnabled !== false`). English readers get nutrition errors through `nutritionEnglish` (`MESSAGES_EN`) — every new Georgian error string there needs an entry.
- **MEDISCAN:** when every reader is down (`isVisionReaderDown`), the answer is a calm 503 „try again later with the same photo/file“, never „unreadable, retake“. Multi-page lab reads skip an unreadable page 1 and name the pages not read (`readLabPages`, `labPagesNotice`).
- **weekly_medi** counts a DOCTOR/CONSILIUM answer (OK, or cut at max tokens); its copy promises a health question, not „a conversation“. Planner answers never count.
- **Medi draft:** closing Medi mid-answer is still Stop, but her question waits in JS memory (`holdMediDraft`, account-bound, consume-once, cleared on send / sign-out / account change) and comes back in the composer on the next plain open — never stored, never sent by itself.
- Open device questions for the owner: whether reading the notification status before `requestPermissionsAsync` on a tap hides the iOS 26 sheet (finding habits F7, four call sites; if it does, keep the permission in state and make the request the first await).

## Launch hardening, train 4 — integration fixes (2026-10-09, ships with app 1.0.0.21.28)

A cross-group review of trains 1–3 plus the owner's main found 18 interactions (three skeptics each). Keep these rules:
- **Dose marks stay in their account.** Medication reminders (slot reminders and moved one-offs) carry `data.owner`; a „მივიღე ✓“ whose owner differs from the signed-in account writes nothing. The device queue (`medicard.meds.pendingDoseLogs`) keeps each row's owner and drains only into it; `AuthContext.adopt()` prunes it to the adopting account (`prunePendingDoseLogs`) before the first `setLocalAccountId` of a credential sign-in — owner-less and other owners' rows are dropped, her own marks stay and drain into her log; a restored session keeps the whole queue. Code that writes queued rows back must also set `pendingMaybe = true`. Dose-log writes re-check `localAccountId()` right before `setScopedPreference`. A queued TAKE cancels the dose's moved one-off; `pullAccountState` cancels moved one-offs whose move ended in the merge (`endedDoseMoves`). Owner-less reminders from older JS are re-stamped at the next medications sync; never cancel a reminder for a missing owner.
- **Medi Stop includes the moment after the last word:** `runTrackedAi` re-checks `cancelled()` after the AI call; the session write and the credit are one transaction inside `req.settleAiOperation` with `gone` read last; an unkept answer's row is removed. 'done' goes out before the quest refresh. `quest:completed` is never emitted for `weekly_medi` (sockets carry no caps; old JS would toast it); MediChat and ScanChat call `requestQuestRefresh()` after an answer. A cut answer counts for weekly_medi whether its status is `ERROR` or the admin's `ERROR_REVIEWED` — admin triage never changes a mission.
- **Cycle:** the one-tap „მენსტრუაცია დაიწყო“ writes day 1 to Health as a cycle start from its two callers only (Home `startPeriod`, /cycle `startPeriodNow`) via `periodStartTapHealthWrite`, never inside `queueApplyPeriod` (the month editor extends past periods with it); the undo cannot remove the sample (cycle samples carry no id). The undo enqueues `SET_LAST_PERIOD(old start)` together with the day's restore in one device-queue save, before any request (durable from the tap); the start plays first (after the day only when the old start was today), through `api.cycle.setLastPeriod`, and `compactCycleQueue` never folds it or a same-day write across it. A restore that saves with a `null` answer or gets no answer (0, 408, 429, 5xx) publishes nothing (`view: null`, the refetch re-plans reminders); only a 4xx shows the start-less view. Never add start/end to its payload or bump the offline store version for a new op (older JS plays an unknown op as a fill that the server refuses; a version bump drops every queued write). A flow-only upsert folded into an earlier same-day upsert patches only its flow (`compactCycleQueue`), and every fold keeps the NEWER write's id so a write made while the older one is in flight is still sent. Web /app keeps an untouched „არ მქონია“ (`sexualStored`).
- **Sessions and devices:** a /me renewal carries `pwc` (the `passwordChangedAt` requireAuth read, ms, 0 = never reset) and requireAuth compares it exactly; tokens without it keep the iat + 5 s rule. When `passwordChangedAt` could not be read (no column or a failed read) the request still passes but `/me` returns no `token` — never sign a fresh token when the reset check did not run. A password reset switches off the account's `PushToken` rows; every sign-in re-registers push (`syncPushRegistration`, no 6 h shortcut). A 401 or `ACCOUNT_BLOCKED` that ends a session in hydrate/adopt runs the local teardown (reminders, push registration memory, pet care) with no request; network errors, 408 and 5xx keep everything. requireAuth's „Account not found“ 401 carries `code: ACCOUNT_NOT_FOUND` — the only 401 the app treats as „deleted“ (a lost DELETE /me answer finishes on retry); device-data wipes key on `jwtSubject(token)`, never on `localAccountId()`. After a server-confirmed delete, discard-new or switch-that-deleted, use `cancelDeviceReminders` (tokens cascaded), never `stopDeviceDelivery`.
- **SMS cap survives deletion:** deleted accounts' sign-in rows keep `SmsLog.destination` as `h:` + an HMAC-SHA256 of the normalized number (keyed with `JWT_SECRET`); `otpCapReached` counts raw and hashed destinations; the admin journal shows them as „[deleted]“.
- Open for the owner: dismissing delivered MEDIPILL notifications on sign-out/delete (closes the last old-JS path and hides the previous person's medicine names from the notification centre).
- **Medi saves never wait for a second connection:** inside an AI save transaction every read uses the transaction client (`getUserPackage`, `loadLimit`, `commitAiCredit` take `db`); Medi and symptom-check saves pass `AI_SAVE_TRANSACTION` (`maxWait 10 s`, `timeout 15 s`), never Prisma's 2 s / 5 s defaults. The stream's error event is built only by `streamErrorEvent` (our own ka/en text, never Prisma text or internal codes; shape `{ type, error, status }` unchanged), and any unkept answer (she left, or the save failed) loses its `AiInteraction` row on both the stream and the JSON path.
