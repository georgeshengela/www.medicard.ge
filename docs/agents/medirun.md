## MEDIRUN economy 2 (owner 2026-10-04, app 1.0.0.20.36)

Owner as business partner: almost no budget, so the game must motivate without paying much. Rules (keep them):
- **Many boxes, few coins, three waves a day, every district.** Tbilisi weekdays 08:00 / 13:00 / 18:00 (evening lit paths only), 5 city + 1 theme box per wave, first finder 20–80 coins; weekends 09:30 / 13:30 / 17:30, 6 + 2 per wave, 30–120; depth ≥ 20 m so 162 of the 255 spots rotate (the two daytime waves cover all ten districts every day — tested). Saturday rain 80 / 150, lanterns 500 (stock 3). Other cities: same three waves, `boxesPerWave` base 2 + 1 per 5 players, max 6. Wave id `md` = შუადღის ტალღა.
- **First-finder ladder** (`economy.decay` = `[100, 60, 40, 25]`, last value repeats): a box opens `stock` times; opening N pays `payoutFor(rule, N-1)` — rounded to 5, never below 5 (`giftRules.js`). The ladder is frozen into `MedipulsiGiftRule.meta.decay` when the box is created (a rule change never alters a box already out); boxes without `decay` (pre-economy-2, plain admin gifts, manual drops with `flat`) pay everyone the same. The claim records `reward.coins` (paid), `reward.rank`, `reward.base`; the ledger row carries `rank`/`base`. `nearby()` tells the app what THIS opening pays (`gift.coins/rank/base/opened/stock`).
- **Season budget** (`economy.budget.seasonCoins`, default 60 000 ≈ 600 ₾ of store value; 0 = unlimited): every MEDIRUN ledger coin inside the campaign dates counts (openings + weekly prizes). `budgetGate` in the autopilot tick: Telegram notice once per `warnAt` threshold (50, 80 %), and at 100 % the autopilot stops placing new boxes (audit `DROP_BUDGET_STOP`, once per day) until the owner raises the budget in admin → წესები → ეკონომიკა. Boxes already out keep paying.
- **Weekly prizes** (`economy.weeklyPrizes.boxes/meters`, default 300 / 200 / 100): Monday 00:10 Tbilisi the previous calendar week's top 3 of each board (opt-in players only) get coins — ledger `week:<monday>:<board>:<rank>`, audit `DROP_WEEK_PRIZES` (idempotent). Paid even while box placement is paused; only the `medirun` module switch stops them. Skill-based, never a draw.
- **Leaderboard** `GET /api/medipulsi/leaderboard?period=week|season&board=boxes|meters`: `week` = this Tbilisi Monday → now (same window as the prizes), `season` = the campaign; `boxes` ranks coins from openings (then boxes, first finds); `me` = the reader's own place even when not opted in (`listed:false`), `prizes` (+ `endsAt`) and `lastWeek` winners. Logic in `server/src/lib/medipulsi/economy.js`; the app's panel shows both boards, „ეს კვირა / სეზონი“, the prize card and last week's winners.
- **Saved rules upgrade themselves:** `campaignRecord` sees `economy.version` < the file's and merges the file's `days`, `saturday` (keeping `dates`), `cities` (keeping `overrides`), `levels`, `economy` over the saved row once (revision + 1, audit `DROP_RULES_UPGRADE`), keeping name, dates, weeks, grand, day overrides, excluded spots. Bump `economy.version` in the JSON whenever the economy blocks change again.
- Copy: boxes say „პირველ გამხსნელს N Medi Coins“ (`coinCopy` in autopilot.js, shared by admin manual drops); the app's hub/drops/schedule say „პირველს“, never „თითოში“; site `/medirun` schedule and rules updated; `decayText()` in `RunDrops.tsx` explains the ladder from the server's `economy.decay`.
- Tests: `server/src/lib/medipulsi/autopilot.test.js` (ladder, budget, week bounds, ranks, upgrade, coverage).
- **Opening moment + wallet (owner 2026-10-04, app 1.0.0.20.37):** the camera finder is gone for now (`GiftInWorld` deleted, owner: „ჯერ ჯერობით თავი შევიკავოთ“). `PulseGift` is one full-screen reveal on a night gradient: the pulse card says „შეეხე და გახსენი“, the sheet shows what this opening pays and the ladder place, „ყუთის გახსნა“ claims (resumes a paused run first — the server still needs a fresh fix within the reveal radius), then the box shakes, bursts into coins, the amount counts up, the rank badge and the new balance appear. ## MEDIRUN in the pocket (2026-10-02, train 1.0.0.19 — store build)

Owner's car test: the screen kept locking, every lock hard-paused the session and nothing resumed. Now (keep all of it): the map screen keeps the screen awake while running (`expo-keep-awake`, released in drive mode); `inactive` (Control Center, call banner, Face ID) never pauses. GPS comes from the background task `medirun-location` (`mobile/src/lib/run/locationTask.ts`, defined from `index.js`; iOS `UIBackgroundModes: location` + blue indicator, Android location foreground service with a notification, `killServiceOnDestroy`; When-In-Use only — never request Always or `ACCESS_BACKGROUND_LOCATION`). Every start/stop goes through one queue, and every launch first stops a task a previous process left behind (OS restores registered tasks), so nothing records outside a running session. A binary without the module falls back to the foreground watch: leaving the app is then a system pause (`autoPaused`) that resumes on its own within 30 min (one retry); a pause the person chose stays paused; cold restore stays paused (Continue). Fixes older than the latest start/resume are dropped. Vehicle: the shared engine (`medipulsi/src/journey.ts` → `node medipulsi/build-core.mjs`, server is authoritative) only flags a vehicle after `VEHICLE_CONFIRM_S` = 4 s of speed (a lone GPS jump is status `surge`, never counted); active time stops while `journey.vehicle` is set; after 3 min in a vehicle drive mode retunes GPS coarser (10 m / 3 s, High) and lets the screen sleep, 6 s at a human pace makes it precise again. In the background: no map messages (PulseActive gates sends on AppState, `mapEpoch` re-sends after a WebView reload — RunMap remounts on content-process/renderer death), no `/nearby` polling, the run snapshot is written directly (Android pauses JS timers).
